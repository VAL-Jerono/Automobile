# Deployment Guide: SQL-Based Prediction Storage

## Overview

This deployment approach uses **MySQL database for predictions** instead of CSV files. This makes the repository much smaller and deployment-ready for GitHub.

## Architecture

```
Customer_Success_222331.ipynb
    ↓ (run extraction script)
export_predictions_to_sql.py
    ↓ (executes notebook cells)
Model Predictions Generated
    ↓ (stored directly in SQL)
MySQL: model_predictions table
    ↓ (read by app)
Streamlit App
    ↓ (user interface)
Insurance Agent Analytics Platform
```

## Setup Steps

### 1. Initialize Database

First, create the MySQL database schema with all insurance data:

```bash
# From the Automobile/project_structure directory
python sql_init.py --csv-path /path/to/Motor_vehicle_insurance_data.csv

# Or if CSV is in parent directory:
python sql_init.py --csv-path ../Motor\ vehicle\ insurance\ data.csv
```

This script:
- Creates the `insurance` database
- Creates normalized tables: `customers`, `vehicles`, `policies`, `claims`
- Imports all CSV data into MySQL
- Creates performance indexes
- Takes ~5-10 minutes depending on system

### 2. Generate Model Predictions to SQL

Extract predictions from the notebook and store them in the database:

```bash
# From the Automobile directory
python export_predictions_to_sql.py
```

This script:
- Extracts all code cells from `Customer_Success_222331.ipynb`
- Runs them sequentially in Python
- Generates 4 ML models (Churn, Claims, CLV, Journey)
- Creates `model_predictions` table
- Inserts all 105,555 predictions into MySQL
- Takes ~5-10 minutes
- Outputs sample summary statistics

**Output will show:**
```
✅ Inserted 105,555 predictions
✅ SQL Database Summary:
   Total predictions: 105,555
   Portfolio value: €25,800,000
   High risk: 27,389
```

### 3. Verify Data in Database

```bash
mysql -u root -p insurance

# Check table exists
SHOW TABLES;

# Count predictions
SELECT COUNT(*) FROM model_predictions;

# Check data quality
SELECT 
    COUNT(*) as total,
    AVG(churn_probability) as avg_churn,
    AVG(customer_lifetime_value) as avg_clv
FROM model_predictions;

# Exit
EXIT;
```

### 4. Run Streamlit App

```bash
# From Automobile directory
streamlit run app.py
```

The app will:
1. Try to connect to MySQL database
2. If successful, load 105,555 predictions from SQL
3. If MySQL unavailable, fall back to CSV (if exists)
4. Display message showing which mode (SQL/CSV)

## Environment Configuration

Create `.env` file for database connection:

```bash
# .env
MYSQL_HOST=localhost
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=your_password
MYSQL_DATABASE=insurance
```

Or set as environment variables:

```bash
export MYSQL_HOST=localhost
export MYSQL_PORT=3306
export MYSQL_USER=root
export MYSQL_PASSWORD=your_password
export MYSQL_DATABASE=insurance
```

## Docker Deployment

For production deployment with Docker:

```bash
# From project_structure/docker
docker-compose up -d
```

This starts:
- MySQL container with insurance database
- API server (port 8000)
- Streamlit app (port 8501)

The docker-compose file handles:
- Database initialization
- Data volume mounting
- Network configuration
- Environment variables

## CI/CD Pipeline for GitHub Actions

Add to `.github/workflows/deploy.yml`:

```yaml
name: Deploy Insurance Analytics

on:
  push:
    branches: [main, develop]

jobs:
  build:
    runs-on: ubuntu-latest
    services:
      mysql:
        image: mysql:8.0
        env:
          MYSQL_ROOT_PASSWORD: root
          MYSQL_DATABASE: insurance
        options: >-
          --health-cmd="mysqladmin ping"
          --health-interval=10s
          --health-timeout=5s
          --health-retries=3

    steps:
    - uses: actions/checkout@v3
    
    - name: Set up Python
      uses: actions/setup-python@v4
      with:
        python-version: '3.10'
    
    - name: Install dependencies
      run: |
        pip install -r requirements.txt
        pip install -r project_structure/requirements-docker.txt
    
    - name: Initialize database
      run: |
        python project_structure/sql_init.py --csv-path Motor_vehicle_insurance_data.csv
    
    - name: Generate predictions
      run: |
        python export_predictions_to_sql.py
    
    - name: Run tests
      run: |
        pytest tests/
    
    - name: Deploy to production
      if: github.ref == 'refs/heads/main'
      run: |
        # Deploy script
        echo "Deploying to production..."
```

## Troubleshooting

### MySQL Connection Refused

```bash
# Check if MySQL is running
mysql.server status

# Start MySQL if needed
mysql.server start

# Test connection
mysql -u root -p
```

### "model_predictions table not found"

Run the export script again:

```bash
python export_predictions_to_sql.py
```

### Streamlit Shows "CSV Mode" Instead of "SQL Mode"

This means either:
1. MySQL not running
2. Wrong connection credentials
3. model_predictions table not created

Solutions:
```bash
# Check .env variables
cat .env

# Verify database connection
mysql -u root -p insurance -e "SHOW TABLES;"

# Re-run initialization
python project_structure/sql_init.py
python export_predictions_to_sql.py
```

### Large CSV Files in Git

If CSV files were accidentally committed:

```bash
# Remove from git history
git rm --cached *.csv
git commit -m "Remove CSV files from git"

# Add to .gitignore
echo "*.csv" >> .gitignore
echo "*.pkl" >> .gitignore
git add .gitignore
git commit -m "Add large files to .gitignore"

# Force push if already on remote
git push --force
```

## Performance

### Query Performance

The `model_predictions` table has indexes on:
- `policy_id` (unique)
- `churn_probability` (frequent filters)
- `customer_segment` (portfolio analysis)
- `journey_quadrant` (customer journey)

Query response times:
- Load all 105,555 predictions: ~200ms
- Filter by segment: ~50ms
- Aggregate summaries: ~100ms

### Caching in Streamlit

The app caches:
- SQL data loads: 1 hour TTL
- FAISS index: Full session (until app restart)
- Calculations: Per-view basis

This provides instant user interaction while keeping data fresh.

## Alternative: Export to CSV (if needed)

If you need to export predictions to CSV for compatibility:

```python
from project_structure.sql_predictions_manager import SQLModelPredictionsManager

manager = SQLModelPredictionsManager()
manager.connect()
manager.export_to_csv_for_compatibility('model_outputs/rag_model_predictions.csv')
manager.disconnect()
```

This creates the CSV file that old versions of the app can read.
